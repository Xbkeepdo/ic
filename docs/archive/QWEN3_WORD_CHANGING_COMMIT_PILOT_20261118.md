# Qwen3：仅提交立即换词的注意力干预

这是原首次类别19层候选的接受策略变体。I/E_l风险、物体词形、前缀类别、目标梯度、视觉注意力回收、FFN空间偏好和强度全部保留；只改变是否提交提案。

原方法在当前目标最终log概率下降时提交。新规则同时要求重算后的贪心token不同于原目标；若概率下降但贪心词不变，恢复原最终隐藏状态和20–35层当前KV。接受的词仍不保证正确，目标是检验减少这类潜在状态扰动能否保留收益。

依据来自首批500图的事后行为诊断：首次保留提案立即换词的23张图贡献9张评估器幻觉消除、无新增；首次不换词的72张贡献2消除1新增。这些分组不是新算法结果，因此先在旧100图运行。新规则在第二批500仍生成时固定；当前第二批原候选配方不改变。

## 实现与预检

`features/qwen3_probe_word_commit.py`继承原完整动作，监听父类接受检查已经计算的LM-head输出取得argmax，没有再调用LM-head。对新拒绝行，按原提案行索引恢复每层当前KV备份，保留其他行的既有决定。事件同时记录原概率下降条件、拟议token、最终接受及新增拒绝原因，区分“概率下降”与“最终接受”。

`scripts/verify_qwen3_word_commit.py`将在GPU0运行两图32步预检：关闭、零预算、强制拒绝的完整logits、token、20–35层当前KV，以及每图首次接受前的逐步logits/KV与SADI精确比较。live分支必须实际触发新增拒绝。若live有更早接受，应另外确认新拒绝发生在可与原生SADI比较的前缀，不能用笼统的前缀帧数代替此分支的证据。CPU及GPU预检均已通过：live两提案均因不换词被拒绝、接受0，全部64个行／步logits及20–35当前KV精确同原生SADI，新增回滚分支已实际验证。

原`head_feedback`审计要求所有概率下降提案都被接受，与新规则不同；不修改该冻结审计器。新`scripts/audit_qwen3_word_commit.py`单独核对两个接受条件、类别历史、拒绝后的原token、无最终接受图片逐token同SADI、探测hidden差和逐批梯度次数。概率下降但被新规则拒绝的提案保留原真实概率差，不把它改写成没有下降。
