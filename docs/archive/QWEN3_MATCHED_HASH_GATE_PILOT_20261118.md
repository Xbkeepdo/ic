# Qwen3：匹配触发率的随机风险门控对照

目的：检验I/E_l检测器对干预目标的选择是否有作用。保持原首次token／首次类别范围、19层注意力操作、视觉目标梯度、FFN偏好、强度和概率下降接受条件，只把检测器门控换成不使用特征的确定性哈希门控。它是贡献对照，不是新的主方法。

## 固定设计

从已完成的原类别首次旧100图运行计数得到：208次允许位置中23次检测器p_real<0.5，固定随机允许率为23/208，约11.06%。计数不使用图片标签，不搜索使结果好的触发率。

对每个允许位置计算`SHA256(seed|image_id|step|token)`，取前8字节的大端整数除以2^64，低于23/208时允许原注意力操作。种子预先固定为43、44、45，全部运行和报告，不选最好种子。在已有原候选的208个位置上，三个种子分别允许24、23、21次；生成轨迹改变后，实际允许次数可以不同。

I/E_l检测器仍计算概率用于记录，但该概率不决定随机臂的动作。事件中的`probe_p_real`保存真实检测器值，另用`gate_score`记录传给继承动作的门控指示；不将0/1哈希指示当作检测概率。后续报告实际提案数、保留数和检测器本会阻止的提案数。这里只匹配期望允许率，没有保证所有方法的实际动作数或注意力移动总量完全相同。

## 复用与设置

旧100图、cap512、maxB16、greedy BF16 eager，两卡沿用原22个有序批次及分片。复用SADI和原首次类别19层候选的完整输出，以及旧trace全部22批图像E_l缓存。每个缓存检查SHA、图像顺序与视觉span。同一批输入和E_l在三个随机臂间共用，模型每卡只加载一次，不重新跑完整SADI或提取图像特征。每卡第一批仅重放SADI前64个token检查环境一致性。

源码`features/qwen3_probe_matched_hash.py`继承原动作，仅替换选择门控和记录；runner为`scripts/run_qwen3_matched_hash_pilot.py`。独立审计`scripts/audit_qwen3_matched_hash.py`重新计算全部哈希、类别历史、实际动作及接受条件，并核对无保留动作图逐token同SADI。原19层关闭／零／拒绝的logits和当前KV一致预检保持冻结；新门控不改变动作或回滚实现。

源manifest包含新三个文件、22个E_l缓存以及所有继承依赖。CPU语法与模块导入通过，导入未初始化CUDA。固定哈希的重复计算、范围和208个校准位置计数已检查。
