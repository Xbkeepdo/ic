# 后续新实验的批次规划：CPU形状检查

当前独立500图保持其已冻结批次。为减少后续任务的尾部小批次，新增一个仅使用图像处理器的规划检查，没有加载模型权重或运行视觉/文本编码器。

调用现有Qwen3包装器的原始输入处理与视觉span定位函数，使用相同AutoProcessor、配置和像素限制。旧100图的视觉token数及原有22个有序批次边界全部精确复现，CPU图像处理循环耗时1.13秒，不含处理器初始化。

如果先在整个图像集合中按相同视觉span和输入长度分桶、每批最多16，再将完整批次分给两卡，这100图可组成16批，两卡各8批。该计划没有用于重新生成或重新评分旧100图。

另从此前已封存500图的原SADI行记录计算：原有61批，其中22个完整16图批；仅按视觉token数合并的批次数下界为48。这只是几何元数据给出的潜在调度改善，不是已经测得的端到端加速。

未来采用全局分桶时，需要在生成前冻结完整batch manifest，所有比较方法在同一计划下重新生成。核查器应对照明确的组内ID和分片清单；不能沿用硬编码的`ids[shard::2]`归属检查。现有旧100图的缓存对照继续使用原22批，不能跨批次计划复用输出。
